# Gnomcode 1.0.0 release notes

Prepared 2026-11-13. This is a release candidate, not publication or launch approval.

## Supported agents

1.0 supports exactly Claude Code, Codex and Antigravity. Removed-agent history remains stored and labeled unsupported. Antigravity can still use Gemini models; Gemini CLI itself is unsupported.

## Sessions and continuity

- A four-place console brings Home, Workspace, Usage and Settings together, with a first-run tour, session groups, provider limit cards, project activity and usage heatmaps.
- Continue an imported conversation in a managed Gnomcode session. Cross-provider handoffs retain redacted local continuity; handoff evaluation reports expose recorded outcomes.
- Opt into an isolated Git worktree for a session, inspect its changes and explicitly merge, discard or open a pull request.
- Session rows and the Workspace list show which surface (for example terminal, IDE or desktop app) a session runs in.
- Review workspace files, diffs and session artifacts. Upload bounded attachments and reuse quick prompts from the console or encrypted Remote.
- Interrupt a running managed session with state-gated, deduplicated Esc delivery. Delivery does not establish native cancellation.

## Approvals and Remote

- Claude Code permission requests can reach the console and paired phone through explicit integration. Timeout or disconnection returns control to native approval; nothing is allowed by default.
- Opt-in protocol launches bridge Codex app-server and Antigravity ACP approval requests. Default launches remain terminal based, with native permissions preserved.
- A held approval raises a notification through the same alert engine as other events, so it is no longer missed when the console is closed.
- Account, approval, onboarding and confirmation dialogs use consistent console controls.
- Releasing or acting on an approval from encrypted Remote refreshes the session activity timer, so a session no longer looks idle right after you respond.
- The mobile web app adds a local passkey or device-PIN app lock and refreshed device/connect screens. This supplements encrypted pairing and does not replace device authorization.

## Limits and reliability

- Provider overviews expose quota state, pace and subscription value with source/trust disclosure. Claude sign-in refresh uses its official CLI, with stale or unavailable readings explained.
- Claude limit/error records and Antigravity RESOURCE_EXHAUSTED improve exhausted-state reporting. Antigravity failures apply to the affected model pool. An opt-in bounded native usage probe provides a fallback when supported.
- Antigravity resumes use the exact conversation ID and restrictive Plan mode. IDE, CLI and newer app records are deduplicated with trajectory usage.
- Claude desktop sessions and child agents stay visible. Completed or stale tool steps stop appearing as running. File watchers back off while idle, and failed host sweeps preserve active hosts.
- Hosted sessions with a still-open tool step stay marked running while live, rather than flipping to idle.
- Long sessions keep their original goal and title when compiled into a model handoff.
- Pending work can inhibit laptop system sleep while Gnomcode runs. This does not wake a sleeping laptop; platform fallback remains documented.

## Desktop and diagnostics

- The tray shows sessions and provider limits. Redacted notifications cover completion, approval and quota events, with per-event settings.
- The updater checks the allowed manifest, stages verified downloads and waits for explicit restart or quit. Failed checks leave the application usable.
- `gnomcode doctor` and the local diagnostic endpoint report environment and service problems.

## Packaging and platforms

- Windows is the verified packaging target. Download names and the update manifest derive from the workspace version, and the updater trusts only a public key pinned into the daemon at build time. A release build without that key is refused by the packaging script.
- macOS and Linux desktop packaging jobs, a cross-platform packaged smoke script and aligned CLI discovery and keep-awake helpers are in place. A platform support matrix and known gaps are documented; those platforms are not yet release-verified.

## Feature defaults

Unproven scheduled-message and account-sync features remain off by default. Enabling them does not establish release acceptance.

## Release acceptance

Windows packaging is the initial verification target. macOS/Linux packages, physical phones, authenticated cross-provider handoffs, clean install/upgrade, signing/OS trust, independent Remote review and legal acceptance remain gates unless separately recorded in the launch checklist. No installer upload, tag, release or website deployment is authorized by these notes.

Coverage baseline: source commit `7cec4e6` ("chore(release): v0.9.4") through `9a20fe9` (current main at preparation). The source repository has no `v0.9.4` tag; Wahaj approved this commit baseline. Do not create a replacement tag without release-time review.

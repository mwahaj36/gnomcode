## 1. Summary

Two different design points, both relevant:

- **agents-dialpad** drives each CLI **headless** (Claude `-p --output-format stream-json`, Antigravity `agy acp` JSON-RPC, Codex `exec --json`) and builds the phone chat from structured events. Because it owns the protocol, it can show real **Allow/Deny cards** for tool permissions (Claude `control_request`/`can_use_tool`, Antigravity ACP `session/request_permission`), stop a turn, and keep a clean transcript. It cannot show the official interactive TUI, and its "full access" mode passes bypass flags, which we must never do.
- **CAO** keeps the **interactive TUI** in tmux and infers status by **scraping the rendered screen** (a pyte terminal emulator, footer-anchored regexes, turn counters). That is the same architecture as Gnomcode's PTY host. Its `lessons-learnt.md` and issue history are a catalogue of exactly the failure modes a screen-scraping design hits: stale buffer matches, dialogs that swallow pasted prompts, prompts pasted before the input box is ready, reworded trust dialogs, spinner glyph drift. Several of those failure modes are live in our code today.

Headline findings against our code (all verified, see section 3):

1. **Phone approval does not exist, and for Claude/Codex tool-permission waits we do not even detect the wait.** `POST /api/v1/sessions/{id}/permissions` only writes a chat row; it never reaches the agent. Remote has no approve, deny or stop request type. The `approval_wait_delay_secs` setting is dead.
2. **A remote or local prompt can be pasted into a Claude Code or Gemini startup dialog.** Our readiness gate covers only Antigravity and Codex. Pasting plus Enter into Claude's "Yes, I trust this folder" dialog would accept workspace trust without the user seeing it. CAO issues #441 and #896 are the same class.
3. **No keep-awake**, although the SPEC promises phone control and scheduled delivery and states the laptop must be awake. Dialpad ref-counts an OS sleep inhibitor around running turns.
4. Several smaller correctness gaps: raw-scrollback `contains` matching, no phone interrupt, Antigravity native resume unsupported, Antigravity limits only while its language server runs, 24 h stale `awaiting_approval`, git viewer lacks `GIT_OPTIONAL_LOCKS=0` and lossy decoding.

What we already do better than both: end-to-end encrypted Remote with device approval, tombstoned deletion, redaction, trust labels, Windows-first paths (desktop-bundled Claude resolution is already fixed at `crates/platform/src/executables.rs:23-27,158-199`), and a quota model with provenance. Neither upstream has anything comparable on privacy.

### 2.2 Status detection and approvals

- **Dialpad**: no status scraping. "Waiting" is an explicit protocol event (`control_request` or `session/request_permission`). Decisions go back as protocol replies. A `Run` object holds pending futures keyed by request id; a decision is idempotent (second tap returns "already decided", HTTP 409), unanswered requests auto-deny after 600 s (`approval_timeout_seconds`), stopping a run cancels pending approvals immediately. Approval payloads cap each string at 20,000 chars and flag truncation. Source: [approvals.py](https://github.com/shazilhamzah/agents-dialpad/blob/main/agents_dialpad/approvals.py), [runs.py](https://github.com/shazilhamzah/agents-dialpad/blob/main/agents_dialpad/runs.py), [SECURITY.md](https://github.com/shazilhamzah/agents-dialpad/blob/main/SECURITY.md).
- **CAO**: `get_status(buffer)` classifies `IDLE / PROCESSING / WAITING_USER_ANSWER / COMPLETED / ERROR` from the rendered screen. Rules worth copying as test cases (fixtures first):
  - Claude spinner line = a spinner glyph plus text plus an ellipsis; the glyph set cycles through `middle-dot, U+2722, asterisk, U+2736, U+273B, U+273D`, so a bare `*` or `middle-dot` frame must count, but only when anchored at line start (a quadratic-regex fix, CWE-1333).
  - Completion = past-tense summary "`<glyph> <Verb> for Ns`" with no ellipsis; the "Waiting for N workflows" background line must NOT read as completed (CAO #392, #393).
  - Own-line effort footer "high / effort" must not read as a response marker (#459). Reduced-motion static glyph spinners false-match finished replies ending in a duration (#974).
  - Waiting-for-user footers for Claude 2.1.310: `Esc to cancel` + `Tab to amend` on one line (tool-permission dialogs), `Enter to confirm` + separator, `up/down to navigate`; classification missed these once and workers read as processing (#1106).
  - Stale permission prompt: count idle prompts after the last permission text; two or more means the user already answered (lessons-learnt 18).
  - Codex 0.155+ ends turns with a "Worked for 32s" footer; trust dialog wording changed in 0.144.1 and broke auto-accept (#410). Antigravity: footer `esc to cancel` = processing, `? for shortcuts` = idle/completed; footer is redrawn in place so only the rendered screen (not the raw stream) is reliable, and a scroll-region reset (`CSI ; r`) must be treated as a full reset (pyte quirk).
- **CAO delivery safety**: never type into an open dialog because the choice widget consumes the paste and Enter picks the highlighted option (#896, `blocks_orchestrated_input_while_waiting_user_answer`). Gate the first paste on real input readiness (#441). After each paste wait for evidence the TUI began processing this delivery; if absent within 8 s send a bare Enter (only when the composer still shows the text) up to twice, never a second paste (issue #78 in docs/inbox-delivery.md). A cached stale COMPLETED must not satisfy the next wait (#407, #735). "edit" on a Claude permission dialog has no free-text field and silently approved the original action (#1114, fixed by offering only approve/deny, #1115).

### 2.4 Phone and PWA UX in dialpad

Installable PWA with network-first shell (`sw.js`), QR pairing, per-device revocable tokens, Web Push (finished, failed, blocked command; generic body by default), lock-screen Allow/Deny action buttons with single-use tokens, WebAuthn app lock (Face ID / fingerprint) with idle timeout and HTTP 423 for locked identities, attachments (extension allowlist, 15 MB per file, 200 MB per chat, sanitized names), git status/diff/revert viewer, owner-defined one-tap quick commands, rename/pin/search/export, continue a desktop Claude session on the phone and copy the resume command back, ref-counted keep-awake, low-limit alerts once per reset window, 7-day usage chart, scheduled prompts, doctor and autostart (scheduled task plus watchdog).

### 2.5 Security choices

Dialpad: static bearer token carried in the URL fragment, loopback bind plus Tailscale Serve, no E2EE, no audit log (their SECURITY.md says so), unlock sessions in memory only, 10 failed unlocks per 10 minutes rate limit, constant-time token compare, project folders as an allowlist, uploads readable by the agent. CAO: bearer auth on the control plane, tool restrictions that are native for Claude (`--disallowedTools`) and only advisory (system-prompt) for Codex and Antigravity, with the docs stating soft enforcement is not a security boundary. CAO also writes agent config files to suppress prompts (`claude_code.py` edits `~/.claude/settings.json` to skip the bypass dialog), which we must not copy.
